# Alpha 0.3 开发整理

核对日期：2026-10-14。依据 GitHub README、公开 Release、main 分支文件清单及本地源码。已完成 TUI 入口切换与六项自动检查；未运行真实 Sysprep、验证 GUI 或重新构建 exe。

## 1. 版本定位

Alpha 0.3 的重点是 TUI 配置向导与执行体验完善。根据用户决定，暂缓 GUI 开发，入口直接启动标准输入输出形式的文本向导；当前不是全屏 TUI。

不将个性化、部署动画、DISM/WIM 管理纳入本版本；沿用后续路线。

## 3. 已有实现

| 模块 | 主要文件 | 当前能力 |
| --- | --- | --- |
| 入口 | `main.py` | 预检、审核模式检查、系统检测、直接启动 TUI |
| GUI | `gui/app.py`、`gui/page_*.py` | 历史实现暂保留，不从入口调用 |
| 配置 | `sysprep/config.py` | 配置 dataclass |
| 控制台 | `sysprep/wizard.py` | 五步输入、最新配置摘要、最终确认与取消 |
| 生成 | `sysprep/unattend/generator.py` | 语言、OOBE、账户、架构与测试/正式输出 |
| 执行 | `sysprep/configured_adapter.py`、`sysprep/executor.py` | 管理员检查、测试模式跳过执行、正式调用 |
| 日志 | `core/logger.py`、`sysprep/log_collector.py` | 程序文件日志、失败日志收集 |

这里的“已有”只表示源码包含功能，不表示通过部署验收。

## 4. 编程顺序与完成条件

### 已完成：先转为 TUI

- [x] 移除入口中的 Tkinter 探测、GUI 初始化与回调。
- [x] 文本向导增加五步提示和最终配置摘要，摘要不包含密码。
- [x] 保持默认测试模式；最终确认默认取消。
- [x] 配置阶段 Ctrl+C 与 EOF 取消后不调用适配器。
- [x] Alpha 0.3 spec 排除 GUI/Tkinter，保留控制台窗口。
- [x] 六项自动检查通过（Python 3.12）：默认取消、最新配置摘要、密码不进入摘要、入口与适配器流程、中断取消、入口无 GUI 导入。

### 暂缓：GUI 确认页与配置一致性

以下两组 GUI 待办保留供恢复 GUI 时处理，不作为当前 TUI 版本发布要求。

- [ ] `gui/page_confirm.py`：进入确认页时重新读取当前配置，更新摘要、按钮文字与颜色。
  - 证据：所有页面在 `_build_pages()` 中一次构建；确认页在初始化时使用默认配置创建文本，之后 `_show_page()` 不刷新。
  - 验收：修改运行模式、计算机名、账户后进入确认页，显示最新值；返回修改后再次进入仍一致。
- [ ] `gui/app.py`：统一下一步、上一步、顶部导航的保存与校验行为。
  - 证据：`_next()` 调用 `collect()`，`_prev()` 和向后导航不收集当前输入。
  - 验收：各导航路径对输入的保留、保存和校验采用明确一致的规则。
- [ ] `gui/page_basic.py`、`gui/page_account.py`：校验成功后再提交配置，避免校验失败时只更新部分字段。
  - 验收：无效输入不会部分覆盖上一份有效配置。

### 暂缓：GUI 执行前后体验

- [ ] 正式执行增加明确确认，展示 Audit/OOBE、generalize 与完成动作。
  - 证据：控制台已有最终确认，GUI 按钮直接调用回调；且确认按钮文案可能因第一步问题与实际配置不符。
  - 验收：用户取消时不写入系统应答文件、不调用 Sysprep。
- [ ] GUI 捕获执行异常，显示失败原因和可用日志路径。
  - 证据：`_execute()` 没有异常处理；入口的外层异常捕获不能保证捕获 Tkinter 回调中的异常。
  - 验收：生成失败、权限不足、Sysprep 非零返回都能给出可见反馈。
- [ ] 测试成功显示应答文件路径；正式执行显示开始与结果状态，执行期间禁止重复触发。
  - 验收：成功或失败后按钮状态合理，测试结果可定位。
- [ ] 处理同步执行造成的 GUI 阻塞。
  - 证据：Tkinter 回调直接进入 `subprocess.run()`。
  - 验收：执行期间界面可响应；若使用后台线程，UI 更新回到主线程。

### 下一步：统一环境与生成验证（发布前必须完成）

- [ ] 明确是否允许普通模式运行测试向导，并分别定义测试与正式模式前置条件。
  - 当前 `main.py` 在收集配置之前拦截非审核模式，默认测试模式无法绕过。
  - 验收：文档、文本向导与实际阻断行为一致。
- [ ] 审查 `sysprep/preflight.py` 中 ActionFiles 目录缺失时仍标记 `ok=True` 的语义。
  - 验收：缺失应清楚显示；是否阻断需根据目标系统验证，不能仅用绿色通过表示缺失。
- [ ] 统一 Sysprep 路径来源，并校验执行模式参数。
  - 生成器使用 `%WINDIR%`，执行器固定 `C:\Windows`；非 `audit` 模式目前直接转为 `/oobe`。
  - 验收：非默认系统目录仍使用同一目标；未知模式被拒绝。
- [ ] 验证应答文件命名空间、各配置阶段与目标 Windows 的接受情况。
  - 当前生成器的根节点没有 `urn:schemas-microsoft-com:unattend` 默认命名空间，需要查照官方格式并验证。
  - 验收：生成文件通过针对目标 Windows 的应答文件验证与虚拟机部署。
- [ ] 检查 ARM64 与现有 x86/amd64 架构选择的边界。
  - 当前 `_architecture()` 用字符串是否包含 `64` 决定 amd64；未单独处理 ARM64。
  - 验收：未支持架构明确拒绝，或经验证后单独支持。
- [ ] 明确账户密码输出行为，避免将真实密码、账户应答文件加入版本库。

## 5. 验收清单

建议正式封装验证使用可恢复快照的 Windows 虚拟机。

| 场景 | 预期 | 当前结果 |
| --- | --- | --- |
| 文本向导确认 | 摘要反映最新配置且不显示密码 | 自动检查通过 |
| 非法计算机名、空账户、非法登录次数 | 重试当前输入 | 待验证 |
| 中文、英文、自定义语言区域 | XML 内容与选择一致 | 待验证 |
| 不支持的 OOBE 选项 | 不询问该选项，生成内容匹配能力 | 待验证 |
| 默认测试模式 | 只输出测试文件，不调用执行器 | 待验证 |
| 最终不确认、配置时 Ctrl+C/EOF | 不进入文件生成与封装流程 | 入口自动检查通过 |
| 正式执行异常 | 控制台显示错误与日志路径 | 待验证 |
| 无 GUI 依赖 | 入口不导入 GUI/Tkinter | 源码自动检查通过；exe 待验证 |
| 非管理员正式执行 | 阻止执行并说明原因 | 待验证 |
| 非审核模式、缺失系统文件 | 符合明确的模式策略 | 待验证 |
| Windows 10/11 Audit 与 OOBE | 生成文件被接受，启动结果符合选择 | 待验证 |
| 打包 exe | 与验收源码行为一致 | 待验证 |

旧 Windows、Server、ARM64 必须分别记录测试结果；在验证之前仅声明代码映射或待支持，不宣传全面兼容。

建议下一次编程先完善 TUI 的环境策略与输入体验，再处理应答文件验证和打包。当前开发环境已迁移至 `.venv37`（Python 3.7.9）；检查范围见 [兼容性记录](PYTHON-3.7-COMPATIBILITY.md)。实际终端交互与部署仍需验证；旧 `.venv38` 保留。

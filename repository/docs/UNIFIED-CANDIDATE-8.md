## 使用方法

完整解压后，以管理员身份运行 Start.cmd。默认 GUI，F8 可切换 TUI；
Start GUI.cmd 和 Start TUI.cmd 可指定模式。根目录两个检查入口分别用于
现代运行环境自检和管理员后台进程诊断；诊断不会执行封装、BCD 操作或电源动作。
Vista 使用自身运行环境内保留的自检入口，不运行现代检查。

不要单独移动 runtimes/modern 中任一 EXE。启动器会检查主程序和辅助程序是否齐全。
主界面仍显示 candidate 7，因为这是直接复用的已验收二进制文件；统一发行包编号为 8。
这不是正式发布版，不替换已有 GitHub Release。

## 回归顺序

1. 在各虚拟机的封装前快照中完整解压，检查中文 GUI、F8/TUI 和关闭窗口。
2. 先使用测试模式生成应答文件，不执行正式封装。
3. Win11 运行 Check background.cmd，确认 hasConsole=false、processInJob=false、completed。
4. 从封装前快照测试正式 OOBE，其他选项与原基线一致；优先 Win11 关机动作，
   随后 Windows 7、8、8.1、10。分别记录实际关机/重启、OOBE 及进入桌面的结果。
5. 若中断，保留现场，运行 Diagnostics/Collect.cmd 后提交桌面诊断包；不要重复封装。

宿主机验证仅包括归档完整性、每个文件哈希、Vista 原样保留、现代两个 EXE 与
候选 7 一致、辅助程序为无控制台 PE 子系统、启动器及路径的静态检查。
不在宿主机启动 EXE、CMD、计划任务、单元测试或封装流程。

复核入口为 tools/check_unified_static.py。旧的运行型回归脚本需要在隔离虚拟机内另行设计，
当前不作为宿主机校验步骤。历史验收记录保留，新包 crossVersionDeploymentValidated=false。
